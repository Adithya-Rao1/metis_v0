# Spec and wireframe traceability

Re-keyed row by row in Wave 5. Every test named below was run and passed (`pytest -q -p no:cacheprovider <ids>`) on the branch this file was committed on; a skipped, xfailed or failing test is called out in its row and is not counted as passing. Suites were run per top-level test directory (mixing `tests/web` and `tests/leadstudio` in one invocation breaks on conflicting `conftest` imports). Browser tests are timing-sensitive: one e2e test failed once under heavy load and passed on rerun alone. Paths are relative to the repository root, tests are `file::test_name`.

Spec: https://claude.ai/artifact/KudmXbhLuoMbWZFZmmvVzw ; wireframes: https://claude.ai/artifact/5jJVkyZNkt617PFQ1N3tyS

Status values:
- covered: the behaviour has at least one named passing test that asserts it.
- partially covered: some of the row is asserted; the gap is stated.
- not covered: the code may exist, but no passing test asserts the row; the gap is stated.
- n/a until real models: cannot be judged until real models are trained and benchmarked (G1-G3). The code path and mechanics tests are listed, but no claim is made about real-model behaviour.

Important context for every "covered" row about predictions: the site runs SYNTHETIC sample models. Tests prove the mechanics (storage, intervals, display, ranking, gating), not that any prediction is chemically right.
